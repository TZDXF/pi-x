# 流式闪烁诊断页

启动：`node node_modules/vite/bin/vite.js --port 1438`

访问：http://localhost:1438/streaming-demo.html

独立 Vite 开发入口，不加载 App、会话状态或后端，也不修改生产聊天组件。

- 左：项目现有 MessageResponse，默认动画。
- 中：同一 Markdown 渲染器，关闭文字动画。
- 右：同一 Markdown 渲染器，按字符动画。
- 三组共享同一个 content；每五批暂停一次，模拟文字淡入完成后继续追加。
- 可编辑 Markdown、批大小、批间隔和暂停时间。重新播放会重置组件和计数。
- requestAnimationFrame 记录同一文字节点从不透明到透明的回落；MutationObserver 记录已经显示的节点被移除。新文字首次淡入不记为回落。
- 这些指标不是闪烁的充分证据：正常 Markdown 格式转换可能移除节点；父级透明度、布局变化和短于采样间隔的变化可能漏检。DOM 采样本身也有性能开销。

2026-09-24 浏览器默认样例验证：三组均输出完成（29 批、230 字符）。透明度回落均为 0；默认动画/字符动画各观察到一次已显示的 `*` 节点移除，关闭动画为 0。尚未据此确认复现用户描述的闪烁，需要使用实际回复继续对比。

## 大文本压测

新增 2 万、5 万、10 万字符预设（段落、列表、表格、代码），默认每批 128 字符、间隔 32ms、无额外停顿。

建议：

1. 先选择 2 万字符、现有组件单组，关闭逐节点诊断，从头播放。
2. 使用同样参数切换到关闭淡入单组，重新播放对比。
3. 若需要快速观察长回复末尾，勾选预填 80%；注意它会把初始解析/大量文字动画的成本一起引入，不等价于从头累计输出。
4. 再逐步增加至 5 万、10 万。三组同时渲染会叠加负载，不能作为单组性能基准。
5. 输出区域独立滚动，可滚动到末尾观察追加文字。

性能指标：前台 requestAnimationFrame 帧间隔（>50ms 次数、最大间隔），以及支持时的 PerformanceObserver longtask（次数、最大耗时）。测量覆盖播放至停止后 1 秒，以包含最后一批渲染；数据每 500ms 更新。它们是整页指标，不可直接归因于 Markdown。默认不启用 DOM MutationObserver 或逐节点样式扫描，降低探针开销。

本轮校验：demo SFC 编译、ESLint、应用生产构建通过。尝试两万字符加预填压测时，内置浏览器连接超时，未取得完整性能数据；不能据此断言渲染器崩溃或确认闪烁原因。

## 自动滚到底

默认开启，可取消勾选查看历史或做滚动开关对照。ResizeObserver 观察输出容器及内部内容高度，覆盖 Markdown 异步布局；通过 requestAnimationFrame 合并滚动操作，先读取各容器高度再统一写入 scrollTop。不使用 smooth 动画，禁用浏览器 overflow-anchor，预留滚动条宽度避免出现滚动条后重新换行。

本轮浏览器验证：30 段、1071 字符、17 批输出完成后，scrollHeight=1094、clientHeight=386、scrollTop=708，距底部为 0。动画组该次运行记录 9 个长任务、最长 136ms；这是含自动滚动和浏览器测试环境的整页观测，不能单独用作闪烁根因证据。
